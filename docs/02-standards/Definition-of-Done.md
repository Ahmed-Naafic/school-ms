# Definition of Done

Version: 1.0

---

# Purpose

This document defines the single, official checklist for when a feature, bug fix, or enhancement is considered complete.

This is the authoritative Definition of Done for the project. Other documents (Project Constitution, AI Development Playbook, Development Lifecycle) reference this document instead of repeating the checklist.

---

# Definition of Done Checklist

A task is NOT complete unless all of the following are true:

☐ Business logic approved

☐ Edge cases reviewed

☐ Technical design completed

☐ Security considered

☐ Validation completed

☐ Development / implementation completed

☐ Standards followed

☐ Code is clean

☐ No known issues remain

☐ Tests passed

☐ Code reviewed

☐ Documentation updated

Only when every item is satisfied is the work marked Done.

---

# Definition of Done Rule

Quality is more important than speed.

Nothing is "mostly done."

A task is either Done, according to this checklist, or it is not done.
